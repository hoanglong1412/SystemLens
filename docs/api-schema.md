## 1. General

### 1.1 Server

| Item | Value |
|---|---|
| URL | `http://127.0.0.1:{port}` |
| `port` | Chosen at startup. Random in production (`--port 0`); `8765` when started by `Tool/run-backend.ps1`. Reported to Electron main through the stdout line `SYSTEMLENS_READY {json}`. |

### 1.2 Security

| Scheme | Type | Applies to | Description |
|---|---|---|---|
| `bearerAuth` | HTTP `bearer` | All endpoints (global `security`) | Random token generated by Electron main for each run, passed to the backend via the `SYSTEMLENS_TOKEN` environment variable. Header: `Authorization: Bearer <token>`. Not required when the backend runs with `--dev`. |

### 1.3 Tags

| Tag | Description |
|---|---|
| `sample` | Sample endpoints: exercise the FE ↔ BE plumbing and serve as reference examples for real APIs. Registered only when the backend is built with `SYSTEMLENS_ENABLE_SAMPLE_API=ON`. |

## 3. Endpoints

<a id="getsamplehello"></a>
### 3.1 `getSampleHello` — `GET /api/v1/sample/hello`

| Item | Value |
|---|---|
| Summary | Return a fixed greeting to prove FE ↔ BE communication works. |
| Tag | `sample` |
| Auth | `bearerAuth` |
| Parameters | none |
| Request body | none |
| Requirement | [FR-SMP-01](requirements/functional-requirements.md#fr-smp-01) |
| Design | [LLD-03](design/lld/LLD-03-sample-hello.md) |

Responses:

| Status | Description | Content type | Schema | Example |
|---|---|---|---|---|
| `200` | Greeting. | `application/json` | [`SampleHelloResponse`](#samplehelloresponse) | `{"message": "@@Hello world@@"}` |
| `401` | [`Unauthorized`](#resp-unauthorized) | `application/problem+json` | [`Problem`](#problem) | — |
| `500` | [`InternalError`](#resp-internalerror) | `application/problem+json` | [`Problem`](#problem) | — |

## 4. Schemas

<a id="samplehelloresponse"></a>
### 4.1 `SampleHelloResponse`

Type: `object`

| Field | Type | Required | Description |
|---|---|---|---|
| `message` | `string` | yes | Always `"@@Hello world@@"`. |

<a id="problem"></a>
### 4.2 `Problem`

Type: `object` — error body (RFC 7807, media type `application/problem+json`).

| Field | Type | Required | Description |
|---|---|---|---|
| `type` | `string` | yes | URI reference identifying the problem type; `"about:blank"` when generic. |
| `title` | `string` | yes | Short, human-readable summary (e.g. `"Unauthorized"`). |
| `status` | `integer` | yes | HTTP status code. |
| `detail` | `string` | no | Human-readable explanation specific to this occurrence. |

## 5. Reusable responses

| Name | Status used | Description | Content type | Schema |
|---|---|---|---|---|
| <a id="resp-unauthorized"></a>`Unauthorized` | `401` | Missing or invalid bearer token. | `application/problem+json` | [`Problem`](#problem) |
| <a id="resp-notfound"></a>`NotFound` | `404` | No route matches the request path. | `application/problem+json` | [`Problem`](#problem) |
| <a id="resp-internalerror"></a>`InternalError` | `500` | Unexpected server-side failure. | `application/problem+json` | [`Problem`](#problem) |

`NotFound` is defined in the contract but not referenced by any endpoint; the backend returns it for any
unknown path (see [LLD-02](design/lld/LLD-02-api-request-pipeline.md)).

## 6. Template for a new endpoint

After changing `api/openapi.yaml`, add a row to section 2 and a block like this to section 3
(and new schemas to section 4):

```markdown
<a id="<operationid-lowercase>"></a>
### 3.N `<operationId>` — `<METHOD> <path>`

| Item | Value |
|---|---|
| Summary | <summary from the YAML> |
| Tag | `<tag>` |
| Auth | `bearerAuth` |
| Parameters | <name (in), type, required, description> or none |
| Request body | <schema> or none |
| Requirement | <FR-...> |
| Design | <LLD-NN> |

Responses:

| Status | Description | Content type | Schema | Example |
|---|---|---|---|---|
| `200` | <description> | `application/json` | <schema> | <example> |
```

Example: [`getSampleHello`](#getsamplehello) above follows this template.
